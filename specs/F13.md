# F13 조선소 챗봇 (MCP · 로컬 LLM)

이미지: chat, chat-hulls. 로그인 사용자 전원. 셸(F02)이 화면 왼쪽 아래에 항상 띄운다.

## 구조

```text
채팅 창 → POST /api/chat → ① 건의/문의 의도 → feedback_kind 응답
                          ② 데이터 질문(규칙) → MCP 서버 도구 (사용자별 서브프로세스, stdio JSON-RPC)
                          ③ 그 외 → Ollama 로컬 모델
```

- 실제 데이터(호선·도면·실적)는 AI에 넘기지 않는다. 규칙으로 고른 MCP 도구가 읽기 전용으로 조회한다.
- 접근 불가 데이터는 모델에도 보내지 않는다.

## MCP 서버 `app/hull_mcp.py`

- 실행: `python -m app.hull_mcp <emp_no>` (cwd=backend). 요청마다 새 프로세스, 줄 단위 JSON-RPC 2.0, protocolVersion `2025-03-26`, serverInfo `shipyard-hulls`.
- 클라이언트(`services/hull_chat.call_tool`): initialize(id 1) → notifications/initialized → tools/call(id 2)을 한 번에 stdin으로 보내고 stdout 두 줄을 읽는다. timeout 10초. 실패·형식 오류는 502 `HULL_MCP_ERROR` `호선 조회 서버에 연결하지 못했습니다.` stdout에는 프로토콜만 쓴다.
- 조회 도구는 `PRAGMA query_only=ON` 연결로, 각 메뉴 View 권한을 확인한다. 권한이 없으면 `{"forbidden":true}` → 라우터가 403.
- 잘못된 인자·도구는 JSON-RPC error -32602.

| 도구 | 입력 | 출력 / 권한 |
| --- | --- | --- |
| search_hulls | `{query≤100}` | `{hulls:[{hull_no,hull_nm,hull_status,progress,delay_count,delivery_dt}] ≤20, total}` / M11 |
| list_drawings | `{}` | `{items:[{drawing_id,drawing_no,drawing_nm,hull_no,dwg_status}]}` / M31 |
| list_progress_hulls | `{}` | `{items:[{hull_no,hull_nm}]}` (F06 progress-hulls) / M22 |
| submit_feedback | `{kind:suggestion|inquiry, content 1~2000, request_id uuid}` | `{receipt:"FB-000123", inquiry_id}` / M95 Write |
| build_report | `{format:pdf|xlsx, hull_no?}` | F14. 업무 오류는 `{error,status}`로 돌려준다 |

## API

- `POST /api/chat` `{messages:[{role:user|assistant, content 1~2000}] 1~12}` (로그인). 마지막이 user가 아니면 400 `CHAT_INPUT` `질문을 입력해 주세요.`
  1. 마지막 문장이 `(건의|문의)(하기| 하고 싶어)?[.!?]?` 전체 일치면 `{answer:"접수할 내용을 입력하고 접수 버튼을 눌러 주세요.", feedback_kind}`.
  2. `공정 실적|실적 (정보|알려|조회)` → list_progress_hulls → `{answer:"어떤 공정의 실적을 볼까요? 먼저 호선을 선택해 주세요.", choice_type:"progress-hull", choices}`(없으면 `공정이 등록된 호선이 없습니다.`).
  3. `도면 … (정보|알려|목록|조회|선택|보여|검색)` → list_drawings → `{answer:"상세 정보를 볼 도면을 선택해 주세요.", choice_type:"drawing", choices}`.
  4. `호선 (의)? (상세|정보|목록|현황|상태|진척|조회|선택|검색)`, `호선…알려`, `SN-숫자` → search_hulls. 검색어 우선순위: `SN-n` > `호선 <번호>` > `<앞말> 호선`의 앞말 > 빈 값. `{answer, hulls}`. 결과 없음 `일치하는 호선이 없습니다. 호선 번호나 이름을 확인해 주세요.`, 20척 초과면 `처음 20척을 표시합니다. 호선 번호나 이름으로 범위를 좁힐 수 있습니다.` 덧붙임. 검색어가 `sn`만이고 결과 없으면 전체 목록 + `‘SN’으로 등록된 호선을 찾지 못했습니다. 등록된 호선 중에서 선택해 주세요.`
  5. 그 외 → Ollama `POST {OLLAMA_BASE_URL}/api/chat` `{model: OLLAMA_MODEL, stream:false, options:{num_ctx:4096,num_predict:320}, messages:[system, ...대화]}`. system: `당신은 조선소 업무 용어와 작업을 설명하는 안내 챗봇입니다. 한국어로 간결하게 답하세요. 시스템의 실제 호선·공정 데이터에 접근할 수 없습니다. 실제 현황은 추측하지 말고 호선 목록이나 상세 화면에서 확인하도록 안내하세요.` 프록시를 쓰지 않는다(ProxyHandler({})). 동시 1건(세마포어), 바쁘면 429 `CHAT_BUSY` `다른 답변을 작성 중입니다. 잠시 후 다시 보내 주세요.` timeout 90초. 오류: 모델 없음(404) 503 `CHAT_MODEL_MISSING` `로컬 채팅 모델을 찾을 수 없습니다.`, 연결 실패 503 `CHAT_OFFLINE` `로컬 모델에 연결할 수 없습니다. Ollama 실행 상태를 확인해 주세요.`, 그 외 502 `CHAT_MODEL_ERROR`/`CHAT_RESPONSE`.
- `POST /api/chat/feedback` `{kind,content,request_id}` (M95 Write) → submit_feedback. 공백만이면 400 `FEEDBACK_INPUT` `접수할 내용을 입력해 주세요.` 같은 사용자·request_id 재전송은 같은 접수번호, 같은 ID에 다른 내용이면 오류(TB_SYS_ChatInquiry로 멱등).

## 화면 `components/ShipChat.vue`

- 런처: 왼쪽 아래(14px, safe-area) 64px 둥근 사각(#def6fa, 테두리 #acdbe4) 안에 CSS로 그린 배 캐릭터(굴뚝·선교·선체·창, 2.6초 흔들림, 움직임 줄이기 시 정지). 닫혀 있으면 오른쪽에 말풍선 `안녕하세요! 친절한 조선소 AI 에이전트입니다.` / `눌러서 질문해 보세요.`(런처 호버 시 숨김).
- 패널: 360×440px(화면에 맞춰 축소), radius 16, 머리 #173d58 `조선소 챗봇` + `로컬 AI` + ×. Esc 닫기, 닫으면 런처로 초점.
- 첫 안내 `안녕하세요! 아래 버튼을 누르고 보고 싶은 항목을 선택해 주세요. 질문을 직접 입력해도 돼요.` 아래 빠른 버튼(알약): 호선 정보(`호선 정보 알려줘` 전송), 도면 정보, 공정 실적, 매뉴얼, 건의하기, 문의하기, `📄 보고서 작성하기`(진한 배경, F14).
- 메시지 말풍선(사용자 오른쪽 #d6eef4), 결과 카드 버튼 목록:
  - hulls: `번호 · 이름` / `상태 · 진척% 또는 계획 없음` → 클릭 시 챗봇 닫고 셸이 호선 상세 모달.
  - drawing: `도면번호 · 도면명` / `호선 · 상태` → 도면 상세 모달(읽기 전용).
  - progress-hull → `GET /api/hulls/{no}/progress-targets?include_done=true` → `{no}호선의 공정을 선택해 주세요.`(없으면 `등록된 공정이 없습니다.`) → progress-plan 선택 → `GET /api/plans/{id}/progress` → `라벨\n상태 {상태} · 진척률 N%\n최근 작업일 … · 누적 N% · 공수 N|미입력 · 인원 N|미입력`(이력 없으면 `등록된 실적 이력이 없습니다.`).
- 매뉴얼 의도: 입력이 `매뉴얼|메뉴얼|사용법|사용 방법|업무 흐름|어떻게 (사용|쓰|보)`를 포함하면 서버로 보내지 않고 매뉴얼(F15)을 연다. 주제: 결재→dwg-approval, 도면→dwg-list, 실적→progress, 공정→plan-gantt, 호선·3d·야드→hull-list, 건의·문의→inquiry, 그 외 dashboard.
- 건의·문의 모드: 입력창 위 `건의 접수`/`문의 접수` + 취소, 버튼 `접수`. 접수 시 crypto.randomUUID request_id(내용·종류가 같으면 재사용), 성공 `접수했습니다. 접수번호 FB-…`, 셸에 알려 열린 건의·문의 탭을 새로고침.
- 대화 전송은 최근 10개(각 2000자)만. 대기 중 `답변을 작성 중입니다…`, 오류는 빨간 말풍선, 실패 시 입력 복원.

## 환경

- 시스템 Ollama를 쓴다(프로젝트 안에 실행 파일·모델을 두지 않는다). 설치·서버 시작·모델 다운로드·추론 검증은 `scripts/setup-ollama.sh`(이미 있으면 건너뜀, 실행 중인 서버는 재사용)가 한다. 백엔드는 `OLLAMA_BASE_URL`·`OLLAMA_MODEL`(기본값 foundation.md)만 읽고 Ollama를 띄우지 않는다. timeout은 설정값.
- 1.5B 모델은 전문 용어 설명이 부정확할 수 있다. 데이터 질문은 반드시 MCP 경로로 간다.

## 수용 기준

CHAT-T01 MCP initialize→tools/call 실제 프로세스, 권한 없으면 403. T02 호선·도면·실적 질문이 각 도구로 라우팅, 카드 클릭으로 상세. T03 건의 접수 멱등, 게시판에 글 생성. T04 Ollama 미실행·모델 없음·바쁨 오류 문구. T05 매뉴얼 의도는 서버 호출 없이 매뉴얼 열기. 테스트에서 Ollama는 대체하고 MCP는 실제 서브프로세스로 검증한다.
