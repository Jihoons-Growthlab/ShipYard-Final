# 구현 인덱스

요구사항 원문은 각 명세에만 있다(한 요구사항 = 한 곳). 이 파일은 순서와 공통 판단 기준만 담는다. 작업 목록은 `state/tasks.json`, 시작은 `scripts/start.sh claim`이 알려 준다.

## 환경 점검 (최초 1회)

`scripts/setup.sh`가 node·npm·uv·Chrome·Unity(+WebGL)·Ollama·한글 글꼴을 점검한다. 결과를 `PROGRESS.md`에 남긴다. Ollama가 없거나 모델·서버가 준비되지 않았으면 사용자에게 `scripts/setup-ollama.sh` 실행을 안내하고(`handoff.sh block`) 나머지를 진행한다.

## 단계 (phase = 세션 하나)

| phase | 작업 | 명세 |

| P1 백엔드 1 | 구성·스키마·시드 / 인증 / 메뉴·날씨·코드 / 호선 / 공정 계획(+schedule) / 공정 실적 | foundation, data-model, F01, F02, F04, F05, F06, rules |
| P2 백엔드 2 | 도면 / 결재 / 회원(+메뉴 권한) / 대시보드 / 사용 로그 / 건의·문의 / 예시 데이터·데모 | F07, F08, F09, F03, F11, F12, F16, rules |
| P3 화면 1 | 인증 / 셸·디자인·날씨·모션·마우스오버 공통 / 호선(+미리보기) / 공정 계획(+드래그·카드·휴일) / 공정 실적(+미리보기) | F01, F02, ui, F04, F05, F06 |
| P4 화면 2 | 도면(+PDF 미리보기) / 결재 / 회원관리(+권한 표) / 대시보드(+업무 흐름) / 사용 로그 / 건의·문의 | F07, F08, F09, F03, F11, F12 |
| P5 챗봇 | MCP 서버·라우팅 / Ollama / 챗봇 화면 / 보고서 PDF·XLSX / 매뉴얼 | F13, F14, F15 |
| P6 Unity·수용 | 3D 단일·fleet 뷰어, 호선 상세 3D 탭, 3D 조선소 / 최종 수용 검증 | F10, F04, 이 파일 |

앞 단계에서 뒤 단계가 필요한 경우:

- P3: 아직 없는 화면은 제목과 조회 전용 배지만 있는 자리표시 화면. 챗봇·매뉴얼 자리는 P5에서 채운다(셸에 마운트 지점만).
- P3 호선: `3D 보기` 탭과 3D 조선소는 P6에서 추가한다.
- P3 공정 계획: 패널의 도면번호 링크는 P4에서 도면 상세 모달에 연결한다.
- P4 대시보드: 도면 개정 영향의 도면 상세 모달을 재사용한다. 업무 흐름 버튼은 P5 매뉴얼이 생기기 전까지 비활성으로 둬도 된다.
- P5 챗봇 접수는 P2의 건의·문의 서비스를 그대로 쓴다.

## 최종 수용 검증

1. 백엔드·프론트 전체 테스트와 프론트 빌드.
2. 시드 직후 값이 `foundation.md` 기준 수치와 같은지(메뉴 13 포함).
3. 계정별: admin(OTP), park.pm, lee.dwg, choi.qa(조회 전용), jung.new(승인 대기 거절). 데모 모드는 `scripts/demo.sh`의 admin/han.wk.
4. 브라우저 시나리오: 가입→승인→로그인 / 호선 등록·삭제 / 공정 추가·연계·간트 드래그 연쇄 / 실적 입력→상태 변화 / 도면 Rev→결재 2단계→배포→공정 READY / 3D 탭·3D 조선소 호버·클릭 / 회원별 메뉴 권한 / 건의 작성→관리자 처리 / 챗봇 호선·도면·실적·건의·보고서 다운로드·매뉴얼 / 사용 로그 집계.
5. 1440x900에서 각 화면을 이미지와 비교. 데이터 변경 시나리오는 fresh DB(예시 데이터 포함)로 실행.

## 기준의 우선순위

명세 > `reference/ui/` 이미지. 이미지의 데이터 값은 시드·예시 데이터 기준이며 하드코딩하지 않는다.

## 알려진 사항 (완성본 기준, 임의로 바꾸지 말 것)

- 실제 TOTP(RFC 6238). 고정 코드 없음. secret 없는 사용자는 OTP를 켤 수 없다(409). QR 등록은 범위 밖.
- 날씨는 항상 샘플. LIVE로 표시하지 않는다.
- PDF: 업로드 파일이 없는 리비전은 안내만 표시한다. 예시 PDF는 `--demo-pdfs`로만 만든다(F16).
- 게이트: 과거 ISSUED 리비전이 있으면 최신이 DRAFT여도 통과. 실적 입력은 게이트를 검사하지 않고, 누적률 역행·음수 공수도 허용.
- 시드 결재 일시 일부가 기준일 이후다. 그대로 둔다.
- 간트 자동 일정 조정은 드래그 schedule API에서만(BR-04). 일반 저장은 조정하지 않는다.
- 제외: 데이터 초기화 버튼, 이슈관리, 블록 독립 메뉴, 비밀번호 찾기, 이메일 인증, CAD 렌더링, 배포 서버 구성, 결재함 마우스오버.

## 시행착오 메모 (토큰 절약용, 이전 구현에서 실제로 겪은 것)

- fpdf2에 `AppleGothic.ttf`를 넣으면 `KeyError: 'OS/2'`. `AppleSDGothicNeo.ttc` collection 0을 쓴다. fpdf2 표의 줄무늬 채움색은 직전 `set_fill_color`가 이어지므로 표 전에 명시한다.
- shots: admin(OTP)은 같은 30초 step 재사용이 거절된다(`otp admin 400`). admin 흐름은 한 그룹으로 묶고 연속 실행 사이에 30초 둔다. 화면 밖 요소를 hover/drag하면 엉뚱한 곳(행 라벨)을 잡는다 — 보이는 막대·좌표 오프셋을 쓴다.
- 미들웨어에서 라우트 템플릿은 `request.scope["route"].path`(호출 뒤)로 읽는다. 사용자 식별은 `current_user`가 `request.state`에 넣는다.
- MCP 서브프로세스는 부모 환경 변수(테스트 임시 DB 경로)를 물려받아야 한다. stdout에는 JSON-RPC만.
- Unity 종료 직후 `Cannot read properties of undefined (reading 'GLctx')` 페이지 오류 1건이 날 수 있다(재진입 영향 없음). WebGL 종료 경고 5건도 같다.
- 공휴일 음영·연결선 층(`pointer-events: none`)이 막대 행보다 위로 오면 클릭·드래그가 막힌다.
- `navigator.pdfViewerEnabled === false`이면 iframe PDF가 빈칸이 된다(F07 대체 표시).
- 문자열 부분 일치로 검사하면 오탐한다(예: `<head` 검사에 `<header`가 걸림).
